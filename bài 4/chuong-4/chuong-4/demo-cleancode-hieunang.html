1. Clean Code HTML

✗ Chưa tốt

<DIV class="Div1">
<div class="div2"><b>Tin mới</b>
<div>Nội dung bài viết
<img src="IMG_2481.JPG">
<div style="color:red;font-size:20px">Xem thêm</div>
</div>
</DIV>

✓ Nên viết

<article class="bai-viet">
  <h2>Tin mới</h2>
  <p>Nội dung bài viết</p>
  <img src="laptop-sinh-vien.webp"
       alt="Laptop cho sinh viên CNTT">
  <a class="nut-xem-them" href="/tin-moi">Xem thêm</a>
</article>
Quy tắc Vì sao
Thẻ và thuộc tính viết thường HTML5 khuyến nghị, nhìn nhất quán
Thụt lề 2 khoảng trắng cho mỗi cấp Nhìn ra ngay cấu trúc lồng nhau
Dùng thẻ ngữ nghĩa thay div Tốt cho SEO và trình đọc màn hình
Đặt tên class có nghĩa, không dấu, dùng gạch ngang .bai-viet chứ không phải .div2
Luôn đóng thẻ, luôn có alt cho ảnh Tránh lỗi hiển thị và lỗi chuẩn W3C
Không viết style="" trực tiếp trong thẻ CSS phải nằm ở file riêng để còn dùng lại
Thêm chú thích cho các khối lớn Mai mốt quay lại còn hiểu mình đã viết gì

2. Clean Code CSS

✗ Chưa tốt

.a{color:#1F509E;margin-top:10px}
div div div span a{color:#1F509E !important}
.b{color:#1F509E}
.c{color:#1f509e}
.a{margin-top:14px}  /* trùng, viết hai nơi */

✓ Nên viết

/* ===== Bài viết ===== */
.bai-viet{
  color: var(--chinh);
  margin-top: var(--cach-3);
}
.bai-viet__lien-ket{
  color: var(--chinh);
}
Quy tắc Vì sao
Nhóm CSS theo từng khối, có chú thích tiêu đề Tìm lại nhanh trong file dài
Dùng biến CSS thay vì lặp mã màu Đổi một chỗ, cả trang đổi theo
Tránh bộ chọn quá sâu (div div div span) Khó ghi đè, chạy chậm, dễ gãy khi sửa HTML
Hạn chế tối đa !important Là dấu hiệu CSS đã rối, sẽ càng khó sửa về sau
Xóa mã không dùng nữa File nhẹ đi, người sau đọc không bị rối
Mỗi thuộc tính một dòng, có khoảng trắng sau dấu hai chấm Dễ đọc và dễ so sánh khi làm nhóm

3. Kiểm tra chuẩn W3C

Công cụ miễn phí của tổ chức W3C, chấm xem mã HTML/CSS của bạn có đúng chuẩn không.

Công cụ Địa chỉ Kiểm tra
HTML Validator validator.w3.org Cú pháp HTML
CSS Validator jigsaw.w3.org/css-validator Cú pháp CSS

Ba cách nộp bài để kiểm tra

  • Validate by URI — dán địa chỉ trang đã đưa lên mạng
  • Validate by File Upload — tải file .html từ máy lên
  • Validate by Direct Input — dán thẳng mã vào ô (tiện nhất khi làm bài tập)

Các lỗi sinh viên hay gặp nhất

Thông báo Nghĩa là
An img element must have an alt attribute Thẻ <img> thiếu alt
End tag for "div" seen, but there were open elements Quên đóng một thẻ nào đó bên trong
Duplicate ID "x" Hai thẻ dùng trùng một id — id phải duy nhất
Element "h1" not allowed as child of element "ul" Đặt thẻ sai chỗ, <ul> chỉ chứa <li>
Stray end tag "p" Có thẻ đóng </p> mà không có thẻ mở
Phân biệt: dòng đỏ Error là lỗi phải sửa. Dòng vàng Warning chỉ là gợi ý, không bắt buộc. Mục tiêu của bài tập: 0 Error.

4. Console trong DevTools

Mở F12 → Console rồi bấm các nút dưới đây. Mỗi nút in ra một kiểu thông báo khác nhau để bạn nhận mặt.

Ký hiệu Mức độ Phải làm gì
Chữ đen Thông tin do mình tự in ra Chỉ để theo dõi
Nền vàng ⚠ Cảnh báo Nên xem lại, chưa gây hỏng trang
Nền đỏ ✖ Lỗi Phải sửa — có thứ đang không chạy

Các lỗi thường gặp trên Console

Thông báo Nguyên nhân Cách sửa
404 (Not Found) Sai đường dẫn file CSS, ảnh hoặc JS Kiểm tra lại tên file và thư mục, chú ý chữ hoa chữ thường
Failed to load resource File không tồn tại hoặc không được nộp kèm Xem tab Network, dòng nào màu đỏ là file đó hỏng
Uncaught ReferenceError: x is not defined Dùng một biến chưa khai báo Kiểm tra chính tả tên biến
Uncaught TypeError: Cannot read properties of null Không tìm thấy phần tử trong HTML Sai id, hoặc thẻ <script> chạy trước khi HTML kịp tải
Mixed Content Trang https nhưng nhúng tài nguyên http Đổi đường dẫn sang https
Ngay lúc này: trang demo này cố tình nhúng một ảnh không tồn tại (anh-khong-ton-tai.jpg) ở ngay dưới đây. Mở F12 → Console, bạn sẽ thấy dòng đỏ 404 (Not Found). Đây chính là lỗi mà rất nhiều bạn gặp khi file CSS không hiện.

Vài lệnh DevTools nên biết

Thao tác Tác dụng
F12 / Ctrl + Shift + I Mở DevTools
Ctrl + Shift + C Bấm chọn phần tử trên trang để xem mã
Ctrl + Shift + M Chế độ xem điện thoại
Ctrl + F5 Tải lại và bỏ qua bộ nhớ đệm (khi sửa CSS mà không thấy đổi)
Tab Network Xem từng file tải về: nặng bao nhiêu, mất bao lâu, có lỗi không
Tab Elements → Styles Sửa CSS trực tiếp để thử nghiệm (tải lại trang là mất)

5. Tối ưu hình ảnh

Hình ảnh thường chiếm 60 – 70% dung lượng một trang web. Đây là chỗ tối ưu được nhiều nhất mà lại dễ làm nhất.

Định dạng Dùng cho
WebP Ưu tiên dùng — nhẹ nhất, mọi trình duyệt đời mới đều đọc được
JPG Ảnh chụp nhiều màu
PNG Ảnh cần nền trong suốt, ảnh chụp màn hình
SVG Logo, biểu tượng — phóng to bao nhiêu cũng nét, dung lượng rất nhẹ 
<!-- loading="lazy": chỉ tải khi người dùng cuộn tới -->
<!-- width + height: giữ chỗ sẵn, trang không bị "nhảy" khi ảnh tải xong -->
<img src="laptop-sinh-vien.webp"
     alt="Laptop cho sinh viên CNTT"
     width="800" height="450"
     loading="lazy">
Công cụ nén ảnh miễn phí: squoosh.app (của Google, chạy ngay trên trình duyệt) hoặc tinypng.com. Kéo ảnh vào, chọn WebP, tải kết quả về.

6. Tối ưu CSS và JavaScript

Việc cần làm Lợi ích
Gộp nhiều file CSS thành một Mỗi file là một lần trình duyệt phải đi hỏi máy chủ — ít file thì tải nhanh hơn
Nén (minify) CSS và JS Xóa khoảng trắng và chú thích, giảm khoảng 30% dung lượng
Đặt <link> CSS trong <head> Trang hiện ra đã có định dạng sẵn, không bị "nháy" chữ thô
Đặt <script> cuối <body> hoặc thêm defer JS không chặn việc hiển thị nội dung
Xóa CSS và thư viện không dùng Nhiều bạn nhúng cả Bootstrap chỉ để dùng một cái nút
Chỉ chuyển động transform và opacity Hiệu ứng mượt, không bắt trình duyệt tính lại bố cục 
<!-- CSS: đặt trong head -->
<head>
  <link rel="stylesheet" href="css/style.css">
</head>

<!-- JS: thêm defer để không chặn việc hiển thị -->
<script src="js/main.js" defer></script>

PageSpeed Insights (pagespeed.web.dev) chạy cùng bộ chấm điểm Lighthouse nhưng trên máy chủ Google, và cần trang đã đưa lên mạng. Lighthouse trong DevTools chạy được cả với file trên máy.

Checklist trước khi nộp bài

  • Mở F12 → Console: không còn dòng đỏ nào
  • Mở F12 → Network: không có file nào báo 404
  • Kiểm tra W3C HTML: 0 Error
  • Ảnh đã nén, có alt, width, height
  • Thử ở chế độ điện thoại (Ctrl + Shift + M): không bị cuộn ngang
  • Nén cả thư mục rồi giải nén ra chỗ khác mở thử — cách chắc chắn nhất để phát hiện thiếu file

Bài tập tại lớp

  1. Chạy Lighthouse cho chính trang này, chụp màn hình bảng điểm và cho biết mục nào bị trừ điểm.
  2. Sửa lỗi 404 ở mục 4 bằng cách thay ảnh giả bằng một ảnh có thật trong thư mục, rồi kiểm tra lại Console.
  3. Lấy bài tập Form của buổi trước, dán mã vào validator.w3.org (Direct Input) và sửa cho đến khi còn 0 Error.
  4. Nén một ảnh bất kỳ bằng squoosh.app sang WebP và so sánh dung lượng trước – sau.
